>
> Parent owner: `N2.02 — Identity / Players`
>
> Sub-owner: `Player Skill Profile`
>
> Finding resolved: `C7-F-006`
>
> This addendum does **not** create a new N2. It resolves ownership of an already-defined cross-context pipeline.

---

# 0. Decision

The canonical ownership is:

```text
N2.02 — Identity / Player
└── Player Skill Profile sub-owner
    ├── PlayerEvaluation semantics
    ├── evaluation revision semantics
    ├── CommunityPlayerSkillProfile
    ├── GlobalPlayerSkillProfile
    ├── aggregation/version provenance
    ├── confidence / missing-state semantics
    ├── Derived Overall formula ownership
    └── profile rebuild semantics
```

The shorthand label `Rating` that appears in older C2/C4/C5 material is therefore normalized as:

```text
Rating
=
N2.02 / Player Skill Profile
```

It is **not** a separate bounded context and must not acquire an independent schema/API authority outside N2.02.

---

# 1. Why N2.02 owns the pipeline

The evaluation/profile pipeline answers a Player-domain question:

> What versioned skill information is currently attributed to this persistent sports identity, and from which Community-level evidence was it derived?

It does not answer:

```text
How should teams be optimized?
What factual events happened in a Match?
Who governs a Community?
```

The persistent subject is the global `Player`; Community is an evaluation context; Team Formation is a consumer; Statistics is a separate factual pipeline.

This keeps ownership stable even if the Team Formation algorithm is replaced entirely.

---

# 2. Boundary with Community

Community owns:

```text
who has Membership / operational responsibility
which evaluator is authorized in that Community
Community isolation / capability context
Community lifecycle that may affect future evaluation eligibility
```

Player Skill Profile owns:

```text
what a PlayerEvaluation means
which revision is effective
how per-attribute evaluation facts are consolidated
how CommunityPlayerSkillProfile is versioned/rebuilt
```

Therefore:

```text
Community authorization
≠
PlayerEvaluation semantic ownership
```

An Organizer may be an eligible evaluator because Community/Session capability policy says so, but N2.02 defines the evaluation/profile data contract.

---

# 3. Boundary with Team Formation

Team Formation owns:

```text
RosterRevision input boundary
ResolveBalanceInputs use case contract
PlayerBalanceSnapshot
hard constraints
soft objectives
solver / algorithm / seed / iteration budget
CandidateSet / Voting / TeamDraw
```

It consumes a frozen, versioned view of skill data:

```text
Community/Global Skill Profile
        ↓ resolver policy
PlayerBalanceSnapshot
        ↓
Team Formation
```

Team Formation does **not** own:

```text
PlayerEvaluation storage semantics
Community/global aggregation estimator
Derived Overall formula
profile rebuild lifecycle
```

Changing the solver must not redefine historical PlayerEvaluation semantics.

---

# 4. Boundary with Statistics / History

The pipelines remain structurally separate:

```text
PlayerEvaluation
→ CommunityPlayerSkillProfile
→ GlobalPlayerSkillProfile
→ Derived Overall
```

versus:

```text
MatchParticipation + MatchEvent + MatchResult
→ PlayerMatchStatContribution
→ Statistics / Career
```

No ownership resolution in this addendum permits automatic mutation between them.

```text
factual Statistics
≠
subjective skill evaluation
```

A future inference model that proposes evaluation changes from Match facts requires its own explicit policy/ADR; it does not collapse these boundaries.

---

# 5. Community-to-global aggregation invariant

The accepted hierarchy remains:

```text
Organizer evaluations by attribute
        ↓
CommunityPlayerSkillProfile
        ↓
GlobalPlayerSkillProfile
```

The global profile does not weight a Community ten times merely because it has ten evaluators while another has one.

The exact robust estimator remains open under `OPEN-RATING-001`.

Possible future credibility weighting remains open under `OPEN-RATING-002`.

Ownership is now closed; estimator parameters are not.

---

# 6. Derived Overall

`Derived Overall` belongs to Player Skill Profile as a versioned derived projection/display helper.

Its ownership does **not** grant it authority over Team Formation.

Non-negotiable:

```text
Derived Overall
NEVER enters
canonical Team Balancer input/objective/ranking/tie-break
```

Changing only the Overall formula must not alter canonical Team Formation candidates.

---

# 7. Missing data and confidence

Player Skill Profile owns the semantic distinction:

```text
missing
≠
0
```

and:

```text
confidence
≠
skill value
```

Team Formation may consume a resolver-produced representation, but missing/cold-start resolution must remain explicit/versioned and may not silently turn absent evidence into a zero skill score.

---

# 8. Authorization and privacy

Ownership of Player Skill Profile does not make evaluations globally visible.

Read/write authorization still composes:

```text
authenticated actor
→ Community context
→ Membership / responsibility / capability
→ Player relation / purpose
→ privacy policy
```

Global Player identity does not imply public evaluation or public Global Skill Profile.

Security/Privacy N2.16 remains cross-cutting authority for privacy, BOLA, RLS/RPC and purpose limitation.
