# 0. Goal

W7 replaces the highest-risk legacy execution model:

```text
Session-wide controller
+ mutable Game score
+ PointEvent sync
+ generic local/cloud reconciliation
```

with:

```text
Match
├── MatchRoster
├── MatchRulesSnapshot
├── MatchControlLease
│   └── control_epoch
├── MatchEvent(sequence)
├── MatchProjection
└── MatchResult
```

Realtime distributes committed facts; offline continuation, when enabled, uses a typed durable command outbox with explicit reconciliation.

W7 is complete for a cohort only when **a new Match cannot be mutated by legacy Game/Point sync or Session-level ownership**.

# 2. W7 rollout strategy

The initial rollout rule is strict:

```text
NEW MATCH V2 ONLY
```

Do not live-migrate an active legacy Game.

Cohort classes:

```text
LEGACY_ACTIVE
→ finish under legacy protocol

LEGACY_FINISHED
→ historical import after terminal state

TARGET_NEW
→ Match V2 from creation
```

A target Session may temporarily host legacy historical Games and new Match V2 records only if the UI/read model clearly separates protocol ownership; one execution instance itself never has two writers.

# 4. XS-W7-02 — PrepareMatch / frozen inputs

Before Match becomes READY/LIVE, create/freeze:

```text
MatchRoster
MatchRulesSnapshot
Court identity
team sides
capture mode
initial projection
```

### Source

MatchRoster normally derives from confirmed TeamDraw/Session roster and preserves exact participant identity/provenance.

### Rules

Community/Session defaults copied into snapshot cannot later rewrite a started Match.

### Fixture

If Match executes a Competition Fixture:

```text
Fixture
≠ Match
```

The Match references the planned Fixture but owns technical execution facts.

### Exit gate

Starting Match never queries mutable current Team membership to reconstruct who was supposed to play.

# 5. XS-W7-03 — MatchControlLease per Match

## Replace current Session ownership semantics

Target:

```text
MatchControlLease
├── match_id
├── controller_user_id
├── device_id informational/coordination
├── control_epoch
├── claimed/heartbeat timestamps
└── expiry/lease status
```

### Authorization

Controller must already be eligible through Session assignment/capability policy.

`device_id` alone is never authentication.

### Claim/takeover commands

```text
ClaimMatchControl
HeartbeatMatchControl
TakeOverMatchControl
ReleaseMatchControl
```

### Epoch

Every successful takeover/reacquisition that invalidates stale control increments `control_epoch` according to target protocol.

### Tests

```text
A controls epoch 7
B takes over → epoch 8
A sends command with epoch 7
→ reject stale control
```

### TTL values

Exact heartbeat/expiry numbers remain `OPEN-MATCH-002`; do not hard-code current 10min/2min as architecture truth without policy/version/config.

### Exit gate

Target Match authorization never calls Session ownership as the authoritative scoring lock.

# 6. XS-W7-04 — AwardPoint semantic transaction

## Input

Client sends sporting intent, conceptually:

```text
match_id
side/team to award
command_id
control_epoch
expected_last_sequence
capture detail if mode/policy permits
```

Client does **not** send authoritative resulting score as source truth.

## Transaction

```text
BEGIN
resolve Match/Session/Community
resolve actor/capability
lock MatchProjection / Match aggregate root
validate LIVE status
validate current lease/controller
validate control_epoch
validate expected_last_sequence
apply frozen MatchRulesSnapshot
append POINT_AWARDED event at next sequence
append derived SET_COMPLETED / MATCH_FINISHED events if rule requires
update MatchProjection synchronously
create/update MatchResult if Match terminates
save command receipt
create committed outbox/broadcast marker if architecture uses one
COMMIT
```

### Response

Authoritative minimal result:

```text
command_id
accepted event sequence
score/current set
last_sequence
match status
match finished? / result reference
```

The controller does not need its own Realtime echo to know whether the command succeeded.

### Idempotency

Response lost after COMMIT:

```text
retry SAME command_id
→ one scoring effect
```

### Concurrency

Two commands both expecting sequence 80:

```text
at most one advances to 81
other gets stale-sequence conflict/refetch/reconciliation semantics
```

### Exit gate

No target scoring path mutates `games.score_a/score_b` or appends PointEvent via generic sync.

```text
→ MatchResult revision if result changes
```

### Manual finish

`OPEN-MATCH-007` must close before broad manual-finish escape paths exist.

### Exit gate

# 8. XS-W7-06 — Match replay / projection integrity

Create a reference replay implementation:

```text
replay(effective MatchEvents + RulesSnapshot)
→ expected MatchProjection / technical result
```

### Required uses

- tests;
- integrity checks;
- migration/historical import validation where enough event detail exists;
- recovery tooling.

### Rule

Projection is rebuildable, but because it is synchronous-critical it is still transactionally maintained for live commands.

### Evidence

```text
stored projection == replay projection
```

on test fixtures and periodic/targeted integrity checks.

### Exit gate

A deliberately corrupted projection is detectable and recoverable from source events.

# 9. XS-W7-07 — Match Realtime contract

Realtime is introduced only after command/source/query semantics work without it.

## Topic scope

Prefer one resource-scoped private channel per Match or equivalent secure scope.

## Envelope

Conceptually:

```text
event_id
type
aggregate_id
sequence
schema_version
occurred_at
minimal payload
```

### Initial convergence protocol

```text
1 subscribe + buffer
2 fetch authoritative Match snapshot/projection with last_sequence
3 discard buffered <= snapshot checkpoint
4 apply contiguous later events
5 gap detected → refetch authoritative state
6 reconnect → refetch/reconcile, not blind trust in missed broadcasts
```

### Payload

Do not expose internal controller/device/command/audit fields to spectators unnecessarily.

Public spectator, if later enabled, uses separate public-safe DTO/channel policy and is blocked by `OPEN-SEC-007` / `OPEN-MATCH-006` until decided.

### Client send

Browser cannot publish authoritative `match.event_committed` facts merely because it knows channel name.

### Exit gate

Dropping/duplicating/reordering a Broadcast cannot permanently corrupt spectator state.

# 10. XS-W7-08 — Match client controller strangler

## Goal

Replace UI assumptions that local mutable Game/Point arrays are the scoring authority.

### Target client flow

```text
UI gesture
→ Application AwardPoint use case
→ MatchCommandPort
→ remote authoritative response
→ local projection/view state update
→ Realtime handles other-client updates
```

### Compatibility

Legacy Game controller remains for `LEGACY_ACTIVE` cohorts.

Router/screen chooses protocol based on explicit Match/Game cohort/protocol version, not by “which record loaded first”.

### No mixed mutation

Target screen cannot simultaneously:

```text
call AwardPoint V2
and
save PointEvent into generic local collection for sync
```

A local offline outbox item is a typed Match command, not a legacy PointEvent mutation.

### Exit gate

Target Match UI has no dependency on `syncService.syncNow()` for scoring correctness.

# 11. XS-W7-09 — Online-first target before offline extension

The target online protocol should stabilize before Community offline live scoring is enabled broadly.

### Minimum online release

```text
PrepareMatch
lease/epoch
AwardPoint sequence/idempotency
projection/replay
Finish/Result
Realtime snapshot/gap recovery
```

### Why

Offline adds a second **temporary transport/storage mode**, not a second authority. It should not hide defects in the base transaction protocol.

`OPEN-MATCH-001` controls whether Community offline live scoring ships in first Match V2 release or remains feature-gated.

# 12. XS-W7-10 — Typed durable Match outbox

If/when Community offline continuation is enabled:

## Local storage

Use IndexedDB structured storage, not broad `localStorage` arrays.

Typed item includes conceptually:

```text
command_id
match_id
command_type
payload intent
control_epoch
base/expected sequence
local order
created_at local diagnostic time
account scope
device scope
status
```

### Durable acknowledgment rule

Offline UI treats a new point as safely recorded only **after the local IndexedDB transaction commits**.

If local durable storage fails:

```text
FAIL CLOSED
```

Do not show a point as safely recorded only in React memory.

### Account isolation

Pending outbox remains scoped/sealed to the User who created it. Logout cannot replay User A commands under User B token.

### Exit gate

Offline pending command survives page reload/crash and never becomes a generic sync record.

# 13. XS-W7-11 — Reconnect / reconciliation protocol

On reconnect:

```text
fetch authoritative lease/epoch/projection/last_sequence
compare local pending chain
```

### Safe case

If:

```text
same effective control epoch
server sequence matches local base chain
commands contiguous and still valid
```

then replay queued semantic commands in order using original command IDs.

### Diverged case

If:

```text
epoch changed
takeover happened
sequence advanced incompatibly
server Match finished/corrected
local chain has gap/corruption
```

then:

```text
RECONCILIATION_REQUIRED
```

No automatic LWW / keep-mine / keep-theirs replacement of whole Match state.

### Old epoch

Old-epoch commands are never automatically applied after takeover even if their client timestamps appear later.

### Reconciliation output

Must preserve local evidence until user/operator recovery decision is completed; pending irreplaceable commands are not cleared as cache.

### Exit gate

Failure test proves controller A offline → controller B takeover → A reconnect cannot duplicate/overwrite B's authoritative chain.

# 14. XS-W7-12 — Historical legacy Game import

After a legacy Game is terminal, classify it:

```text
LEGACY_COMPLETE_ENOUGH
LEGACY_PARTIAL
SCORE_ONLY
AMBIGUOUS
```

### Import rules

If ordered PointEvents are trustworthy:

- preserve event identities where possible;
- derive sequence deterministically from provable source order;
- verify replay against trusted result.

If final result is trustworthy but detailed events are not:

```text
create Match historical shell/result
capture_coverage = SCORE_ONLY / LEGACY_PARTIAL
```

Do not manufacture events to reconcile score.

Conflicting source evidence becomes MigrationAnomaly/manual review.

### Competition

Importing MatchResult does not automatically make it OfficialCompetitionResult; W8 owns officialization policy.

### Exit gate

Every imported Match has provenance/capture class explaining what is known vs unknown.

# 17. Dependency degradation matrix

## Realtime down

```text
controller command may still succeed through authoritative API/DB
spectator updates degrade/refetch
source truth remains correct
```

## Notification provider down

No effect on Match source transaction.

## Statistics projector down

AwardPoint still commits; W9 projection catches up later.

## Network lost on non-offline-enabled Match

Client clearly reports command unavailable; it does not fake committed success.

## IndexedDB fails in offline-enabled Match

Fail closed before local durable acknowledgment.

## Telemetry exporter down

Normal Match command remains successful unless a separately required atomic audit policy says otherwise.


