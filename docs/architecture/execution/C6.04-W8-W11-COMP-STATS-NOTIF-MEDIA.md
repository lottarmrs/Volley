# 0. Goal

W8–W11 migrates four downstream areas only after their source boundaries are trustworthy:

```text
MatchResult
→ Competition officialization
→ Statistics contributions/projections

Committed Domain Event / Outbox
→ Notifications

Untrusted upload
→ MediaAsset READY
```

These waves are intentionally downstream-heavy. They must not become alternate authorities for Match, Registration, Team Formation or identity.

# 2. W8 — Competition

## XS-W8-01 — Competition root / ruleset schema

### Target concepts

```text
competitions
competition_ruleset_versions
competition_administrator_assignments
competition_entries
competition_teams
competition_roster_revisions
```

### Rules

Competition is an edition/organized competitive structure, not a Session type.

Competition administration is separate from Community Organizer/MatchController.

Ruleset is versioned/frozen according to competition lifecycle before official play.

### Migration

Legacy Championship UUID may be preserved as Competition UUID when it clearly identifies the same edition.

Ambiguous legacy type/rules remain evidence; do not invent Stage semantics from label alone.

### Exit gate

A new target Competition can exist without creating a fake Session or relying on Session `type=tournament`.

---

## XS-W8-02 — Stage / Group / Round / Fixture normalization

### Target

```text
competition_stages
competition_groups
competition_rounds
fixtures
fixture_slot_sources
```

### Semantic boundary

```text
Round
≠ Fixture
≠ Match
```

Round groups zero or more Fixtures; Fixture plans a pairing; Match is concrete execution.

### FixtureSlotSource

Typed source examples:

```text
DIRECT_ENTRY
GROUP_POSITION
STAGE_POSITION
FIXTURE_WINNER
FIXTURE_LOSER
SEED
BYE
```

No opaque rank strings as permanent dependency graph.

### Legacy migration

Current `ChampionshipRound` rows that behave as confrontations normally map to Fixture, optionally grouped into a target Round if source semantics support grouping.

Never:

```text
one legacy ChampionshipRound row
→ automatically one target CompetitionRound
```

### Exit gate

Target scheduler/bracket can represent multiple Fixtures in one Round and fixture dependency without string parsing.

---

## XS-W8-03 — Competition scheduling commands

Target commands/queries include:

```text
GenerateCompetitionStages
GenerateFixtures
ScheduleFixture
RescheduleFixture
ResolveFixtureSlots
GetStage
ListStageFixtures
GetBracket
```

Scheduling is separate from execution.

A Session may host Fixtures, but Fixture identity/competition dependency remains Competition-owned.

Captain-negotiated reschedule remains `OPEN-COMP-005`; do not grant Captain admin mutation by default.

## XS-W8-04 — Match execution association

### Flow

```text
Fixture
→ PrepareFixtureExecution
→ Match V2
→ MatchResult
```

A Fixture can have zero, one or multiple Match executions when replay/invalidation policy requires.

One Match execution never becomes the Fixture row itself.

### Exit gate

Replaying/invalidating a Match does not require destroying Fixture planning history.

---

## XS-W8-05 — OfficialCompetitionResult

### Target

```text
official_competition_results
```

with version/supersession semantics for corrections.

### Command

```text
OfficializeMatchResult
CreateAdministrativeResult
CorrectOfficialResult
```

### Critical boundary

```text
MatchResult
≠ OfficialCompetitionResult
```

A finished Match does not update standings until Competition policy creates a current official result.

### Auto-officialization

Default remains explicit officialization unless `OPEN-COMP-002` closes for selected formats.

### Walkover

Administrative result may carry regulatory score, but does not generate fake MatchEvents/player stats.

### Exit gate

Standings change only from current official result/penalty facts, never directly from mutable Game status.

---

## XS-W8-06 — StandingsProjection / penalties

### Target

```text
competition_penalties
standings_projections
```

Projection source:

```text
current OfficialCompetitionResult
+ current Penalties
+ versioned ruleset/tiebreak policy
```

### Rebuild

Standings must be deterministically rebuildable from sources.

### Performance

Hot standings read projection instead of recomputing whole history client-side.

### Realtime

Low-frequency semantic invalidation/update is sufficient:

```text
official_result.changed
standings.invalidated
stage.updated
fixture.updated
```

Client refetches authoritative projection.

### Exit gate

Deleting projection in isolated test and rebuilding produces same standings.

---

## XS-W8-07 — Bracket propagation / retroactive corrections

### Dependency propagation

When upstream official result changes:

- resolve only future compatible dependent slots;
- never silently replace participant of downstream Match already started/completed;
- preserve old official result revision.

### Commands

```text
PreviewOfficialResultCorrectionImpact
CorrectOfficialResult
```

### Manual impact gate

If correction affects already-started downstream execution:

```text
MANUAL IMPACT REVIEW REQUIRED
```

### Exit gate

A correction cannot silently rewrite semifinal/final history.

# 3. W9 — Statistics / History

## XS-W9-01 — MatchParticipation as historical source boundary

### Target

`MatchParticipation` records actual historical participation according to capture/lineup semantics, separate from current Team membership.

### Migration

For legacy Match/Game where exact on-court participation cannot be known:

- preserve roster/known participant evidence;
- classify participation/capture coverage honestly;
- do not claim precise stats unsupported by source.

`OPEN-STAT-002` governs exact gamesPlayed semantics where rostered-but-never-entered becomes representable.

### Exit gate

Removing Player from current Team does not alter historical played matches/stat contribution.

---

## XS-W9-02 — PlayerMatchStatContribution

### Target projection/source relationship

```text
MatchParticipation
+ effective MatchEvents
+ MatchResult / OfficialResult eligibility
→ PlayerMatchStatContribution
```

Each contribution records:

```text
match_id
player/participant identity
capture coverage
source_last_sequence
stat_definition_version
calculation_version
calculated_at
```

### Missing semantics

```text
0
= captured and did not happen

UNKNOWN
= not captured / insufficient evidence
```

A SCORE_ONLY Match cannot assert zero aces/blocks merely because no detailed event exists.

### Exit gate

Contribution recompute from source Match facts matches stored projection for covered metrics.

---

## XS-W9-03 — Scoped aggregate projections

Target read scopes:

```text
Match
Session
Community
Competition
Global Career
date range
```

Hot projections/read models may be materialized; rare queries may aggregate bounded contributions.

### Anti-double-count

Exactly one effective contribution per eligible Match/player/stat definition chain.

Quick provisional local contribution is superseded by server contribution after publish, not added beside it.

### Exit gate

Publishing one local Quick cannot increase gamesPlayed twice.

---

## XS-W9-04 — Remove subjective rating from factual history

### Current issue

Legacy Career artifacts may contain rating/Overall display values.

### Migration

Do not import them into factual stat contribution.

If historical UI value must remain visible:

```text
LEGACY_DISPLAY_EVIDENCE
```

separate from factual statistics.

### Exit gate

Changing evaluation/Overall cannot mutate factual Career totals.

---

## XS-W9-05 — Statistical eligibility / official Competition stats

Competition-specific official stats use explicit eligibility policy.

Technical Match events may exist before officialization, but official Competition ranking/awards include only eligible official source according to rules.

WO creates classification result but no fake player events.

`OPEN-STAT-003/005` govern abandoned-match/sample policies.

### Exit gate

Invalidated/non-official Match can be excluded deterministically without deleting its technical history.

---

## XS-W9-06 — Stats read cutover and legacy projector retirement

### Sequence

1. produce target contributions in shadow for Match V2;
2. compare target projection to independent fixture/manual expected values;
3. historical import/backfill by Match identity/capture class;
4. cut selected Career/Stats queries to target read model;
5. retain legacy adapter only for not-yet-migrated history;
6. measure target-vs-legacy traffic;
7. remove broad client `allGames/allPoints/allTeams` aggregation after full coverage.

### Exit gate

Main target Career screen/query does not need full historical PointEvent dataset in browser.

# 4. W10 — Notifications

Notifications start only from trustworthy committed source events/outbox.

## XS-W10-01 — Domain outbox adoption by selected source command

### Target

Introduce/extend `domain_outbox` in same transaction as source fact.

Candidate first events:

```text
RegistrationPromoted
SessionPublished/Changed where useful
TeamDrawConfirmed / VoteFinalized
MatchFinished
OfficialCompetitionResultChanged
```

Do not emit every DB row change. Outbox event is semantic and versioned.

### Rule

If outbox insert is required for reliable downstream effect, it is atomic with source transaction.

Provider call is not.

### Exit gate

Crash after source COMMIT but before worker execution cannot lose the durable notification intent source signal.

---

## XS-W10-02 — NotificationPolicy / NotificationIntent

### Target

```text
notification_policies/configuration
notification_intents
notification_inbox/read state
```

One intent is recipient-centric and references source event/context.

### Rules

- recipient derived from domain/source policy, not arbitrary browser `user_id`;
- template/policy version attributable;
- rendered content may be frozen/snapshotted according to target N2.10;
- persistent Inbox does not depend on external Push/Email provider.

### Exit gate

A valid domain event can create one idempotent intent per intended recipient even if worker reruns.

---

## XS-W10-03 — DeliveryAttempt / provider adapter

### Target

```text
delivery_attempts
push endpoints / channel-specific destination records
```

Worker model:

```text
at-least-once
+ idempotent logical delivery handling
+ bounded retry/backoff
+ quarantine/terminal failure
```

Provider outage never rolls back source domain action.

Provider choice remains OPEN; adapter boundary ships first.

### Exit gate

Provider timeout/crash-after-side-effect does not duplicate domain fact and follows channel idempotency/reconciliation policy.

---

## XS-W10-04 — Scheduled reminders with revalidation

A scheduled reminder stores source reference/policy, but before delivery revalidates:

```text
recipient still eligible?
Session/Registration/Fixture still relevant?
revision/status still current?
notification suppressed/cancelled by newer state?
```

Withdrawn participant must not receive stale “session soon” reminder solely because a job was scheduled earlier.

### Exit gate

State change after scheduling suppresses obsolete reminder deterministically.

---

## XS-W10-05 — Realtime Inbox acceleration

Notification intent is durable first.

Realtime may emit:

```text
notification.inbox_changed
```

to prompt user-scoped Inbox refetch.

Missing Broadcast cannot lose NotificationIntent.

### Exit gate

Realtime outage leaves Inbox correct.

---

## XS-W10-06 — WhatsAppShareDraft boundary

Existing WhatsApp list/template artifacts remain **manual share artifacts**.

Do not migrate:

```text
WhatsAppListDraft
→ DeliveryAttempt
```

because draft composition is not proof of sending/delivery.

Future automated WhatsApp provider, if adopted, enters Notification provider model separately with legal/consent policy.

### Exit gate

No historical draft is reported as delivered notification.

# 5. W11 — Media

## XS-W11-01 — MediaAsset schema / identity

### Target

```text
media_assets
media_upload_intents / processing records as needed
media_variants
media_attachments or domain asset pointer
```

Identity:

```text
MediaAsset.id
```

not URL/bucket path.

Domain examples:

```text
Player.avatar_asset_id
Community.avatar_asset_id
Community.cover_asset_id
```

### Exit gate

Changing Storage host/bucket/variant URL does not change media identity referenced by domain entity.

---

## XS-W11-02 — Private upload intent

### Flow

```text
CreateMediaUploadIntent
→ authorized purpose/owner/limits
→ private incoming object path
→ browser direct upload using constrained authorization
→ FinalizeMediaUpload
```

Raw user bytes are never written directly into public final namespace.

### Security

Object key avoids PII; intent scoped to actor/purpose/size/time.

### Exit gate

Guessing another user's incoming object path cannot read/attach it.

---

## XS-W11-03 — Server-side processing/sanitization

Processor validates actual decodable media, not just client MIME/extension.

Baseline:

```text
byte limits
format/decode
pixel/dimension limits
malformed/pixel bomb defense
EXIF/GPS removal
orientation normalization
animation policy
canonical re-encode
```

V1 format baseline remains conservative; SVG/animation unsupported unless future policy changes.

Browser resize may remain upload optimization but is not security authority.

### State

```text
UPLOADED/PROCESSING
→ READY
or FAILED/QUARANTINED
```

### Exit gate

A spoofed PNG/script, pixel bomb and EXIF GPS fixture cannot become READY unprocessed.

---

## XS-W11-04 — READY-before-attachment switch

Replacing avatar/cover:

```text
new raw upload
→ new sanitized MediaAsset READY
→ atomic domain pointer switch
→ old asset becomes unreferenced candidate according to retention/GC policy
```

Never clear old good attachment before new asset is READY.

### Reliability

If processing fails, old READY asset remains active.

### Exit gate

Media worker/provider failure cannot leave domain pointing at raw/FAILED asset.

---

## XS-W11-05 — Public/private delivery variants

Preferred trust zones conceptually:

```text
incoming private
sanitized private master
approved/public variants when visibility permits
```

Private/contextual assets use authorized/signed delivery rather than exposing raw storage path publicly.

Public asset DTO exposes only delivery-safe URL/variant metadata, not internal processing path.

### Exit gate

Pending/rejected/private asset is not public merely because public CDN/bucket exists elsewhere.

---

## XS-W11-06 — Legacy avatar migration

Inventory:

```text
players.avatar_url
proposal rows/state
Storage object paths
external URLs
current ownership/approval
```

### Migration flow

```text
legacy reference
→ classify trusted source
→ safely fetch/read
→ decode/validate/sanitize
→ create MediaAsset READY
→ attach avatar_asset_id
```

External URL ingestion requires SSRF-safe downloader policy; privileged worker never blindly requests arbitrary private-network URL.

### Compatibility

Temporary read adapter:

```text
avatar_asset_id READY
→ target delivery
else
→ legacy avatar_url
```

New target writes create MediaAsset only.

### Exit gate

Telemetry confirms no target avatar write produces raw URL identity and legacy fallback use reaches removal threshold.

---

## XS-W11-07 — Orphan cleanup / quota

GC runs after grace period and rechecks references before deletion.

It is idempotent and must never treat all unreferenced-looking incoming objects as disposable without considering in-flight upload/processing state.

Quota/rate limit can consider:

```text
bytes
pixel count
processing CPU frequency
concurrent uploads
failed abuse attempts
```

Exact numerical limits remain OPEN/benchmark-driven.

### Exit gate

GC cannot delete currently referenced READY asset in race with attachment/replacement.

# 8. Rollback / forward-fix

## Competition

After official result exists, never roll back by rewriting source Match or deleting old official version. Use correction/supersession.

## Stats

Fix projector/calculation version and rebuild derived projections; source Match facts remain untouched.

## Notifications

Disable provider/event-family generation for new intents if defective; preserve already committed domain facts and durable Inbox/intents. Repair/retry delivery separately.

## Media

If new processor/variant release fails, stop new upload finalization or pointer switch; existing READY assets continue. Do not revert domain pointer to raw upload.
