# 0. Goal

W12–W14 removes the broad local-first/generic-sync architecture **only after each shared bounded context already has a target authority path**.

The sequence is:

```text
W12
build explicit local authority/storage for things that truly belong offline

W13
subtract migrated shared entities from generic sync one by one

W14
remove dead compatibility contracts/schema/code only after evidence
```

The goal is not “delete local data”.

The goal is:

```text
LOCAL STATE HAS EXPLICIT SEMANTICS
```

instead of every entity being implicitly synchronizable.

# 2. W12 — IndexedDB structured local store

## XS-W12-01 — Define local data classes physically

Create structured local stores conceptually equivalent to:

```text
local_quick_sessions
local_quick_participants
local_quick_roster_revisions
local_quick_team_draws
local_quick_matches
local_quick_match_events
match_command_outbox
local_drafts
remote_cache_snapshots
migration_import_state
recovery_state
```

Exact IndexedDB wrapper/library remains implementation choice unless an Open Decision elevates it.

### Local data classes

Every store/record must declare one of:

```text
IRREPLACEABLE_LOCAL
RECREATEABLE_CACHE
LOCAL_DRAFT
CONDITIONALLY_REPLAYABLE_COMMAND
MIGRATION/RECOVERY_METADATA
```

### Rule

A migration failure can discard recreateable cache if safe; it cannot delete irreplaceable Quick/Match data as generic recovery.

### Exit gate

One point/event update is a bounded IndexedDB transaction, not full-domain `JSON.stringify()` rewrite.

---

## XS-W12-02 — Account/device scoping

### Preserve useful current behavior

Current `LOCAL_CACHE_OWNER_KEY` recognizes that local domain cache must not be mixed between accounts; device ID is informational rather than authority.

Target strengthens this:

```text
local record owner scope
anonymous/device scope where applicable
account switch boundary
sealed pending data
```

### Logout/account switch

```text
stop replay/workers
close current logical scope
clear in-memory authenticated state
seal irreplaceable pending commands to original account
activate next account scope
```

Never replay User A pending Match commands under User B token.

### Anonymous local data

Anonymous Quick data is not auto-claimed merely because a User logs in.

Import/claim is explicit.

### Exit gate

Cross-account local isolation tests cover cache, Quick and outbox.

# 3. XS-W12-03 — Quick Session local-owned aggregate

## Authority model

Before publication:

```text
QuickSession authority = LOCAL DEVICE
```

This is not “pending cloud sync”.

### Local workflow

Quick can perform offline:

```text
create Session
add Guest/linked participants as locally available
configure rules
create RosterRevision
resolve/freeze balance snapshots
run Team Formation
choose/confirm TeamDraw locally
prepare/start/control local Match
record Match events durably
finish local Session
```

### IDs

Use final UUIDs locally from creation. Do not introduce parallel `cloudId` identity.

### History

Local Quick remains irreplaceable until explicit publish/export/discard.

### Exit gate

Airplane-mode Quick can complete core flow after app shell is available, without pretending server state exists.

# 4. XS-W12-04 — PublishQuickSession one-way authority handoff

## Goal

Turn a local-owned Quick into server-owned shared/history state through one explicit protocol.

### Preflight

Before publish:

```text
validate authenticated identity/context
validate local aggregate integrity
calculate canonical content/source fingerprint
ensure all final UUIDs/references coherent
ensure no unresolved local corruption
```

### Command

```text
PublishQuickSession
command_id
local aggregate identity/fingerprint
versioned payload/snapshot package
```

The exact server import contract may use multiple internal inserts but remains one semantic handoff.

### Client authority states

```text
LOCAL_OWNED
→ HANDOFF_IN_FLIGHT
→ SERVER_OWNED
```

Unknown response case:

```text
server may have committed
client timed out
→ HANDOFF_UNKNOWN
```

### HANDOFF_UNKNOWN rule

Client must not continue editing as confidently `LOCAL_OWNED` because two authorities may now exist.

Recovery:

```text
retry/query with SAME command_id / handoff identity
resolve receipt/server Session
→ SERVER_OWNED
or confirmed not committed
→ return to LOCAL_OWNED through explicit state resolution
```

### One-way rule

After `SERVER_OWNED`, connectivity loss does not automatically make Session local-owned again.

### Exit gate

Commit-success/response-loss test produces exactly one server Session and no split authority.

# 5. XS-W12-05 — Quick historical/statistical publish reconciliation

When local Quick becomes server-owned:

```text
server validates/imports source facts/snapshots
```


### Exit gate

# 6. XS-W12-06 — Key-by-key localStorage importer

Do not migrate localStorage by copying one giant object into IndexedDB.

Classify every current key.

## 6.1 Move/import to IndexedDB where semantically valid

Potential categories:

```text
vpg_session_draft
→ LOCAL_DRAFT

Quick-like local-only session/game/point/team data
→ explicit local-owned Quick stores after classification

vpg_sync_issue_ledger useful support data
→ migrate only useful diagnostics/recovery semantics; do not preserve generic sync architecture
```

## 6.2 Remain small localStorage candidates

```text
vpg_active_community_id
vpg_dismissed_hints
device id
small UI preferences
```

These remain non-authoritative.

## 6.3 Recreateable shared cache

Examples such as cloud-sourced Communities/Players may be discarded/refetched once target read caches exist, but only after account scope and target availability are known.

## 6.4 Ambiguous local domain data

A local Session with `communityId` but no trustworthy cloud counterpart is **not** automatically published as shared Community Session.

Classify:

```text
LEGACY_UNRESOLVED_SHARED_LOCAL
```

and require explicit import/review/recovery.

### Importer properties

```text
versioned
idempotent
checkpointed where needed
account-scoped
source-preserving until verification
records per-key/per-entity result
never auto-claims unknown-owner data
```

### Deletion

Old localStorage source is deleted only after:

```text
successful import/refetch classification
+ semantic verification
+ grace/recovery policy
```

### Exit gate

Interrupt importer halfway, restart, and prove no duplicate/lost irreplaceable local facts.

# 7. XS-W12-07 — IndexedDB schema migration/recovery policy

IndexedDB upgrades must distinguish cache from irreplaceable data.

### Migration pattern

```text
inspect current DB version
→ backup/export metadata if required
→ incremental schema upgrade
→ batch/checkpoint large data transformations
→ verify record counts + semantic references
→ mark migration complete
```

### Failure

Do not use:

```text
catch migration error
→ delete entire IndexedDB
```

when local Quick/outbox exists.

### Recovery UX

May include:

- retry migration;
- local export/recovery bundle if introduced;
- quarantine malformed record;
- discard only recreateable cache;
- user-visible “local data needs recovery” state.

### Exit gate

Corrupt cache can be removed without deleting valid Quick/outbox; corrupt irreplaceable record becomes explicit recovery condition.

# 9. XS-W13-02 — Stop target writes through sync

For a fully cut-over capability, remove/deny the sync upload path first.

Examples eventually include:

```text
Community target mutation
Session target roster/rules/organizer
Registration (never generic sync in target)
TeamDraw/Voting
Match V2
Competition target
Stats projections
MediaAsset
NotificationIntent
```

### Guard

A target record mistakenly presented to legacy upload adapter should be rejected/ignored safely, not converted back to legacy row.

### Exit gate

Telemetry shows zero successful generic-sync target mutations for the capability.

# 10. XS-W13-03 — Stop target reads/merge through sync

After target Query/read models serve all supported UI:

- remove entity from generic cloud download;
- remove merge path;
- remove remapping for target representation;
- delete compatibility cache entry only after refetch path is proven.

### Critical rule

Do not leave a merge routine that can resurrect a stale legacy copy into target cache/UI after write cutover.

### Exit gate

Target screen loads correctly with generic sync disabled for that entity.

---

# 11. XS-W13-04 — Retire semantic dedup/remapping where no longer valid

Current sync performs semantic deduplication and ID/reference remapping because local/cloud identities historically diverged.

Target identity uses final UUIDs and explicit migration mapping.

Retire per-entity logic only after:

```text
all target entities use final ID
legacy local aliases mapped through migration provenance
remaining historical imports use dedicated migrator
no active writer creates new local/cloud duplicate identities
```

### Important

Do not delete migration alias/provenance merely because runtime sync remap disappears. Historical traceability can outlive runtime compatibility.

# 12. XS-W13-05 — Retire `syncStatus` / `cloudId` / generic `deletedAt` from target types

### Sequence

1. target domain types no longer require these fields;
2. compatibility mapper keeps them only in legacy adapter type if needed;
3. UI stops displaying generic sync status as domain lifecycle;
4. runtime search/import fitness tests ensure new target code does not use them;
5. remove from shared canonical type definitions;
6. contract DB fields later W14.

### Replacement concepts

```text
command outcome / pending outbox status
cache freshness
aggregate revision
Match sequence
domain lifecycle status
migration state
```

rather than one generic sync enum.

### Exit gate

Target domain model compiles without sync metadata fields.

# 14. XS-W13-07 — Global `syncService` deletion gate

`src/infra/supabase/syncService.ts` becomes deletable only when:

```text
[ ] no target shared writer calls it
[ ] no target shared reader requires it
[ ] every LocalSyncPayload entity has explicit target/local/retired policy
[ ] no critical pending mutation exists only as syncStatus=pending
[ ] Quick uses explicit local ownership
[ ] Match uses typed outbox/reconciliation where offline enabled
[ ] caches are recreateable/refetchable
[ ] residual legacy local data importer/recovery exists
[ ] semantic dedup/remap no longer needed at runtime
[ ] telemetry shows no supported client/cohort dependence
[ ] architecture tests/docs are updated with removal
```

Deletion before those conditions is an outage/data-loss risk, not cleanup.


### Migration style

Use dedicated contract migration after observation period. Avoid bundling many unrelated destructive drops into one opaque migration.

## XS-W14-02 — Legacy service/module removal

Potential candidates:

```text
communityCloudService generic mutation methods

careerCloudService after target Stats read migration
```

### Fitness tests

Architecture tests that imported/validated legacy contracts must be updated or deleted with explicit replacement invariant.

Do not keep dead abstractions because a fitness test references them.

---

## XS-W14-03 — Legacy localStorage key deletion

Each retired key has a removal proof:

```text
imported successfully
or classified recreateable and target refetch works
or feature/domain retired
```

Never run a broad `localStorage.clear()` migration.

### Old keys after grace period

A lightweight cleanup can delete known retired keys after importer/version marker confirms safe handling.

Unknown keys are not automatically assumed safe domain data, but also should not be blindly appropriated.

---

## XS-W14-04 — Compatibility DTO/view/RPC removal

Remove target→legacy adapters only after:

```text
supported client versions no longer call them
UI route/component migration complete
telemetry confirms no traffic
migration/import tooling no longer depends on them
```

Public/stable external contract, if later introduced, needs explicit deprecation window independent from internal UI migration.

---

# 17. Failure scenarios / required evidence

## IndexedDB / Quick

```text
[ ] browser reload after local Quick point preserves it
[ ] quota failure fails closed for irreplaceable write
[ ] interrupted DB upgrade preserves recoverable Quick
[ ] cache corruption can be discarded independently
[ ] account switch never mixes outbox/Quick scopes
[ ] anonymous Quick does not auto-claim to login account
```

## Publish handoff

```text
[ ] commit success + lost response → HANDOFF_UNKNOWN
[ ] retry same command_id → one server Session
[ ] SERVER_OWNED never silently returns LOCAL_OWNED after disconnect
[ ] local provisional stats superseded after publish without double count
```

## Importer

```text
[ ] rerun idempotent
[ ] source not deleted before verification
[ ] ambiguous shared local Session quarantined/reviewed
[ ] unknown owner data not assigned to current User
```

## Sync retirement

```text
[ ] every payload entity appears in retirement ledger
[ ] target writer disabled from generic sync first
[ ] target read works with sync download disabled
[ ] no stale legacy merge can overwrite target cache
[ ] syncService deletion gate checklist complete before deletion
```

## Contract

```text
[ ] fresh DB migrations still work after contract migrations
[ ] supported old-client traffic is zero/within explicit retirement decision
[ ] no DB function/RLS/index references removed columns
[ ] restore drill after contract works
[ ] docs/runbooks/fitness tests no longer prescribe retired path
```

# 18. Rollback / forward-fix

## IndexedDB importer defect

Pause importer version; do not delete legacy source. Ship fixed idempotent importer.

## Quick publish defect before commit

Return to LOCAL_OWNED only after confirmed no server authority was created.

## Quick publish unknown outcome

Stay `HANDOFF_UNKNOWN`; resolve with receipt/server query.

## Sync subtraction breaks a screen

If aggregate authority already target:

```text
restore a READ compatibility adapter if safe
```

not the legacy writer/merge authority.

## Contract migration defect

Prefer forward-fix/compatible restoration of required column/view where possible. Do not assume down migration can reconstruct dropped semantic data.

# 20. C6 W12–W14 exit statement

W12–W14 is complete when the repository can truthfully say:

```text
Quick is offline because Quick owns its local authority before publish,
not because every domain entity is cached and merged.

Shared state is online-authoritative because commands commit on the server,
not because sync eventually picks a winner.

Match offline is safe because commands are fenced by epoch/sequence,
not because a newer timestamp wins.

Local storage is structured by data criticality,
not one JSON database.

Legacy code is removed because evidence proves nobody needs it,
not because a rewrite reached the end of a checklist.
```
