# 0. Purpose

The execution packs describe what to build and how authority moves.

This document defines **when a slice is allowed to move to the next state**.

The governing rule is:

```text
CODE COMPLETE
≠
CUTOVER READY
```

and:

```text
CUTOVER ACTIVE
≠
LEGACY REMOVABLE
```

A target path can be correct in isolation and still be unsafe to enable because migration evidence, observability, old-client compatibility, recovery or negative authorization testing is missing.

# 1. Gate taxonomy

## G0 — Architecture / decision gate

Required questions:

```text
owner known?
ADR(s) known?
GINV/local invariants known?
Open Decisions identified?
conservative behavior defined?
```

A BLOCKING Open Decision must close before the dependent irreversible/privileged behavior ships.

## G1 — Schema / contract expand gate

Required:

```text
additive/backward-compatible schema where applicable
migrations-from-zero pass
RLS/grants defined
delete/FK semantics reviewed
runtime contract schema/version defined
no destructive legacy removal bundled prematurely
```

## G2 — Owner-layer correctness gate

Required according to domain:

```text
unit/property
real DB transaction
RLS/BOLA
concurrency
replay/rebuild
IndexedDB durability
failure injection
```

Q0/I0/Q1/I1 invariants are not waived because E2E is green.

## G3 — Compatibility / migration gate

Required:

```text
backfill/import idempotent
provenance recorded
anomalies classified
legacy compatibility bounded
authority ledger updated
no second writer introduced
```

## G4 — Cutover readiness gate

Required:

```text
server/schema deployed first where needed
client compatible
target read/write path telemetry available
kill/pause control available
rollback/forward-fix understood
runbook for high-risk slice
```

## G5 — Cutover verification gate

Required after enabling cohort:

```text
target traffic observed
legacy writer absence for cohort confirmed
error/conflict/integrity signals acceptable
semantic invariants checked
no unexpected authority drift
```

No contract removal yet.

## G6 — Legacy read/write retirement gate

Required:

```text
all supported UI paths use target
legacy writer zero/blocked
legacy read traffic zero or explicit residual cohort only
old-client compatibility policy satisfied
migration anomaly handling complete
```

## G7 — Contract/destructive removal gate

Required:

```text
search/code dependency check
DB function/view/RLS/index dependency check
job/worker dependency check
runbook/doc dependency check
restore/backup implications checked
fresh migration chain passes
production/target telemetry proves removal safety
```

# 2. Risk tiers and mandatory gates

Use N2.21 operational risk classes conceptually:

```text
R0/O0 — local reversible
R1/O1 — bounded additive
R2/O2 — high shared correctness/security
R3/O3 — destructive / authority / recovery critical
```

## R0

Typical:

```text
pure UI copy
non-authoritative view refactor
```

Needs normal CI; architecture slice may be informational.

## R1

Typical:

```text
additive read model
shadow projection
new compatibility adapter
```

Needs G0–G2, and G3 where data copied.

## R2

Typical:

```text
Registration command
Community capability/RLS
Match command/control
officialization
Player link
media attachment
```

Needs G0–G5 before production cohort.

## R3

Typical:

```text
drop legacy column/table
bulk identity merge
production reset
restore/cutover
privacy deletion repair
syncService final removal if residual local data at risk
```

Needs full G0–G7 plus rehearsal/restore evidence appropriate to blast radius.

Every architecture-relevant PR should include enough metadata to answer:


This is not ceremony for every CSS change; use it for architecture-relevant slices/risk tiers.

# 4. Slice Definition of Ready

A slice is `PLANNED` but not implementation-ready until:

```text
[ ] owner N2 identified
[ ] target ADR(s) accepted
[ ] C5 matrix row/relationship known
[ ] Q0/Q1 global/local invariants identified
[ ] blocking Open Decisions resolved or feature safely scoped out
[ ] current code/schema touchpoints inventoried
[ ] authority before/after explicitly written
[ ] migration/backfill class known
[ ] required test layer known
[ ] rollback/forward-fix strategy described
```

Tooling choices can remain OPEN when they do not alter semantic safety.

---

# 5. Slice Definition of Cutover Ready

```text
[ ] target schema deployed and backward compatible
[ ] target command/query implementation deployed
[ ] RLS/capability path tested at owner layer
[ ] migration/backfill successfully rehearsed if required
[ ] target client is compatible with current/target server window
[ ] protocol/cohort selector explicit
[ ] target-path telemetry visible
[ ] legacy writer behavior for target cohort is blocked/known
[ ] failure path/unknown outcome tested
[ ] operator pause/kill control exists for high-risk rollout
[ ] migration provenance/anomaly handling ready
```

---

# 6. Slice Definition of Verified

Verification means more than “no exception in logs”.

```text
[ ] authoritative rows/facts satisfy domain invariants
[ ] target command/result telemetry observed
[ ] legacy writer attempts = zero or explicitly blocked for cohort
[ ] target read parity/semantic expectation verified
[ ] no cross-scope auth leakage
[ ] concurrency/sequence/revision behavior matches model
[ ] async downstream lag/backlog within understood state
[ ] user journey functions under target authority
[ ] no unresolved migration anomalies affecting cohort correctness
```

For projections:

```text
rebuild == stored projection
```

where the target calls them rebuildable.

---

# 7. Definition of Legacy Write Disabled

A slice reaches `LEGACY_WRITE_DISABLED` only when:

```text
legacy UI cannot invoke legacy writer for target cohort
legacy service rejects/ignores target protocol records safely
sync/upload path cannot mutate target source
old client behavior is blocked/compatibly routed according to policy
telemetry can detect attempted legacy mutation
```

Merely preferring the new code path in current UI is insufficient.

---

# 8. Definition of Contract Eligible

A legacy field/table/service is `CONTRACT_ELIGIBLE` when:

```text
writer = 0
reader = 0 for supported clients/cohorts
backfill/provenance complete
compat adapter = 0 traffic or formally retired
DB internal references = 0
jobs/workers = 0 dependencies
runbooks/docs updated or archived
restore/recovery does not require legacy representation
```

Contract eligibility is separately reviewed from the original cutover.

# 10. Recommended first implementation sequence

C6 waves are architectural dependency order. For practical implementation, the first executable sequence should minimize blast radius while increasing proof capability.

## Batch A — Safety and test substrate

```text
XS-W0-01 architecture-risk guardrails
XS-W0-02 inventory/authority ledger
XS-W0-03 DB/RLS/concurrency harness
XS-W0-04 RPC hardening baseline
XS-W0-05 command infrastructure spike
XS-W0-06 migration provenance
XS-W0-07 path/release telemetry
```

No domain authority needs to move yet.

## Batch B — Low-blast-radius domain correctness

```text
XS-W1-01 Overall removal from solver influence
XS-W1-02 factual Career anti-contamination boundary
```

This yields immediate architectural correctness without schema migration dependency.

## Batch C — First shared target vertical slice

Prefer one Community/authorization path because it exercises:

```text
semantic command
RLS
capability
migration mapping
server authority
client use case
telemetry
```

Suggested order:

```text
CommunityMembership/CommunityPlayer split foundation
→ Organizer capability resolver
→ CreateCommunity/ownership invariant
→ JoinRequest target command
→ generic Community writer cutover for new Community cohort
```

This validates the strangler mechanics before high-risk Match/Registration.

## Batch D — Session + Registration

Build target Session backbone, then use Registration as the first serious concurrency proof.

## Batch E — Rating + TeamFormation

W1 solver correction already landed; connect it to authoritative snapshots/provenance.

## Batch F — Match V2 online-first

Only after earlier command/RLS/concurrency patterns have been exercised.

Offline Community Match can remain feature-gated until the online event/control protocol is proven.

# 11. Change ordering inside one vertical slice

Preferred pattern:

```text
PR A — schema expand + constraints + RLS skeleton
PR B — owner-layer DB/RPC tests + semantic command
PR C — Application port/use case + runtime contracts
PR D — compatibility read adapter / shadow path
PR E — migration/backfill + parity/invariant verification
PR F — target UI/cohort cutover + telemetry
PR G — disable legacy writer for cohort
PR H — remove legacy reader after evidence
PR I — later contract migration
```

Not every tiny slice needs nine PRs. The rule is that **expand, cutover and destructive contract remain reviewably distinct** for high-risk work.

# 12. Database migration gate checklist

Every authoritative migration answers:

```text
Does it rewrite/lock large table?
Is it additive?
Can old app still run after it?
Can new app run before it? (should normally be no; deploy server/schema first)
What FKs/delete actions change?
What RLS/grants/functions depend on it?
Is backfill required?
Can backfill restart?
How is semantic completion verified?
What happens on partial deploy?
What restore version compatibility exists?
```

For contract migrations additionally:

```text
old-client usage proven gone?
compatibility view/RPC gone?
backup/restore/runbook updated?
```

# 17. Observability gate checklist

Do not require every numeric SLO before rollout, but require enough signal to know if the migration is correct.

Per cutover:

```text
legacy-path usage
target-path usage
command/query outcome
conflict/rejection family
migration anomaly count
projection/integrity mismatch where applicable
worker/outbox backlog where applicable
protocol/release/cohort version
```

High-cardinality User/resource IDs are diagnostic trace/log fields only when needed and privacy-governed, not normal metrics.

# 18. Open Decision gate rules

## BLOCKING

Slice cannot enable dependent behavior until resolved.

Examples:

```text
PlayerAccountLink approval authority before broad claim
waitlist ineligible handling before skip/promotion policy ships
public spectator visibility before public channel
post-finish correction authority before privileged correction surface
health/minors processing before expanding those data uses
```

## DEFERRED

Feature remains absent; unrelated architecture continues.

Examples:

```text
reserved registration slots
payments
advanced public/intercommunity competition
```

## EVIDENCE-TRIGGERED

Do not decide prematurely.

Examples:

```text
Redis
read replicas
partitioning
message broker
server-side solver
persistent staging
specialized observability collector
```

Implementation must not choose these merely to complete a wave.

# 19. Authority contradiction preflight

Before cutover, answer for one concrete resource:

```text
Who accepts next write if client is current?
Who accepts next write if old client is open?
What does generic sync do if it sees the record?
What does offline mode do?
What does Realtime do?
What happens after feature flag OFF?
What happens after browser reload?
```

If any answer yields two independent writers, the slice is not cutover-ready.

# 20. Critical recovery preflight

## Registration

Can failure between withdrawal/promotion leave partial state? Must be no.

## Match

Can response loss duplicate a point? Must be no.

Can old controller after takeover replay automatically? Must be no.

## Quick

Can timeout after publish leave both device and server confidently authoritative? Must be no; `HANDOFF_UNKNOWN` exists.

## Competition

Can retro correction silently rewrite downstream Match? Must be no.

## Notifications

Can provider outage roll back source fact? Must be no.

## Media

Can failed processing replace valid avatar with broken/raw object? Must be no.

For every Q0/I0 or Q1/I1 global invariant affected by a slice, the PR/release evidence must name the proof class.

Examples:

```text
GINV Registration FIFO
→ DB + CONCURRENCY

GINV Match sequence/epoch
→ DB + CONCURRENCY + FAILURE + REPLAY

GINV BOLA protection
→ RLS + SECURITY

GINV Overall excluded
→ TYPE + PROPERTY + DIFFERENTIAL

GINV irreplaceable local durability
→ OFFLINE/IndexedDB failure tests

GINV account deletion preserves sports history
→ DB + privacy workflow + RESTORE
```

If the test suite cannot prove an invariant at its owner layer yet, the release gate remains incomplete.

# 23. C7 preflight checklist

Before C7 begins, C6 must expose enough information for contradiction audit.

```text
[ ] every wave W0–W14 has execution path
[ ] current concrete legacy mechanisms are named
[ ] target authority after each cutover is explicit
[ ] compatibility patterns are bounded
[ ] active-cohort non-migration rules explicit
[ ] backfill fabrication prohibitions explicit
[ ] Open Decisions referenced rather than silently closed
[ ] test/observability gates mapped
[ ] rollback/forward-fix rules explicit
[ ] contract-removal proof defined
[ ] no universal sync replacement introduced
```

C7 will then search for mismatches such as:

```text
ADR says one authority but C6 slice implies dual writer
C4 says Overall excluded but compatibility adapter still feeds it
C5 says online-only but C6 queues command offline
N2 says source fact append-only but migration overwrites history
Open Decision unresolved but C6 assumes exact value
legacy doc/test still appears normative after target supersession
```

# 24. C6 Definition of Done

C6 is complete as an architecture-execution phase when:

```text
1. W0–W14 have concrete execution slices and gates;
2. current repository touchpoints are named;
3. authority transfer is explicit by cohort;
4. target schema/API/client order is explicit;
5. backfill/import/provenance behavior is explicit;
6. compatibility is one-way/bounded where necessary;
7. release evidence is defined by invariant criticality;
8. unknown outcome/recovery/rollback semantics are explicit;
9. legacy retirement is evidence-driven;
10. C7 can audit C1–C6 without needing to infer the migration plan from conversation history.
```

C6 does **not** mean all slices are implemented. It means implementation no longer needs to invent the migration architecture.
