# 0. Governing separation

```text
OFFLINE POLICY
= who may accept a mutation while dependencies are unavailable?

REALTIME
= how committed/shared changes reach interested clients faster?

RELIABILITY
= how correctness/durability/recovery survive failure?
```

These are different questions.

```text
Realtime down
≠ app globally offline

cache exists
≠ local authority

provider retry
≠ domain retry
```

# 1. Operation-level offline matrix

| Operation | Offline class | Local behavior while offline | On reconnect | Why |
|---|---|---|---|---|
| read cached Community | `CACHED_READ` | show last-known + freshness/stale label | refetch authoritative snapshot | cache is not authority |
| edit Community settings form before submit | `LOCAL_DRAFT` | draft may persist locally | submit semantic command when online | draft has no shared effect |
| approve/reject JoinRequest | `ONLINE_AUTHORITATIVE` | unavailable; no queued fake success | explicit user retry/refetch | governance/capability current state matters |
| role change / ownership transfer | `ONLINE_AUTHORITATIVE` | unavailable | explicit retry after online/auth readiness | security/high-impact shared state |
| create Quick Session | `OFFLINE_OWNED` | full local source/current/snapshots | remains local until explicit Publish | deliberate local authority |
| edit/play Quick Session | `OFFLINE_OWNED` | durable IndexedDB local operations | no automatic cloud handoff | local authority by product design |
| Publish Quick Session | `ONLINE_AUTHORITATIVE` handoff | cannot complete offline | explicit one-way handoff; unknown outcome recovery | authority transfer requires server commit |
| create Community Session | `ONLINE_AUTHORITATIVE` | local draft allowed, no shared Session success | submit when online | shared Session UUID/state must be authoritative |
| Join Registration | `ONLINE_AUTHORITATIVE` | do not queue; do not claim slot/position | refetch + explicit Join | capacity/FIFO/time current |
| Leave Registration | `ONLINE_AUTHORITATIVE` | do not queue as authoritative leave | refetch + explicit Leave | leave+promotion must be atomic now |
| capacity/open/close/lock Registration | `ONLINE_AUTHORITATIVE` | unavailable | refetch + command | ordering and current queue semantics |
| Generate Team candidates from trusted snapshot | `LOCAL_COMPUTATION` | solver can continue | publish/confirm waits for server revalidation | computation is pure, authority is not |
| Publish CandidateSet | `ONLINE_AUTHORITATIVE` | keep local candidate draft/result only | server revalidates source revisions/hard constraints | shared selection state |
| CastVote | `ONLINE_AUTHORITATIVE` | no queued ballot | refetch round state + cast if still OPEN | deadline/eligibility/one effective vote |
| ConfirmTeamDraw | `ONLINE_AUTHORITATIVE` shared / local Quick | Quick can confirm locally; Community waits online | shared server validation | roster/current draw race |
| normal Community Match point while online | `ONLINE_AUTHORITATIVE` | server command path | receive authoritative response/realtime | source MatchEvent sequence lives server-side |
| ongoing Community Match after connectivity loss, if feature enabled | `CONDITIONALLY_OFFLINE_COMMAND` | persist allowlisted ordered command in Match outbox only if prior control context valid | epoch/sequence reconciliation | special availability protocol, not generic sync |
| Match takeover | `ONLINE_AUTHORITATIVE` | impossible safely offline | server creates/fences new epoch | old controllers must be invalidated globally |
| Match correction/official result | `ONLINE_AUTHORITATIVE` | unavailable | explicit current-state action | high-integrity history/competition effect |
| Competition mutation/officialization | `ONLINE_AUTHORITATIVE` | unavailable | refetch + semantic command | shared official state |
| Stats/Career read | `CACHED_READ` | cached projection may display with freshness | refetch/rebuild server projection | browser is not career authority |
| local Quick stats | `OFFLINE_OWNED` derived overlay | compute provisional local projection | server recomputes after publish; local overlay superseded | avoid double counting |
| Notification Inbox read | `CACHED_READ` with server durable authority | cached list may show | refetch from cursor | Realtime/Push not durability source |
| MarkRead | server-authoritative current recipient state; offline support only if explicitly approved | do not invent arbitrary queue semantics | idempotent command if/when policy allows | `OPEN-NOTIF-005` |
| media upload | `ONLINE_AUTHORITATIVE` for shared asset creation | local file preview/draft only | CreateUploadIntent + upload | server processing required before READY |

### Absolute prohibition

A generic “queue any mutation and replay later” API must not accept:

```text
JoinRegistration
LeaveRegistration
CastVote
Community role/ownership mutations
Competition officialization
Match takeover
```

# 2. Local storage matrix

| Local data | Store target | Recreateable? | Account scope | Durability rule | Eviction/reset behavior |
|---|---|---:|---|---|---|
| Quick Session aggregate/source facts | IndexedDB | no until publish/export/discard | user or explicit anonymous device scope | commit locally before UI says safe | never delete as cache repair |
| Quick MatchEvents | IndexedDB | no until handoff/discard | same Quick owner scope | append durable before acknowledgement | preserve through restart/migration |
| Match command outbox | IndexedDB | no until server ack/reconcile/discard | authenticated User + device/context | persist before showing offline point as safe | never replay under another User |
| local drafts | IndexedDB | usually not source truth but user work may be valuable | explicit user/device scope | best-effort according to draft value | no automatic cross-user claim |
| remote cache snapshots | IndexedDB | yes | user/context scope | freshness/version metadata | first candidate for pruning/reset |
| migration/recovery metadata | IndexedDB | important during migration | account/device scope | idempotent/recoverable | preserve until migration verified |
| theme/small UI prefs | localStorage | yes/low-risk | local device/user preference | LWW can be acceptable | may reset |
| device identifier | localStorage/small storage | replaceable | device only | not authorization | may regenerate with diagnostic consequences |
| auth token | auth provider storage mechanism | security-sensitive, not app domain store | current auth session | never copied into app recovery exports/logs | provider/session lifecycle |

### Account switch sequence

```text
stop outbox/replay/workers
→ seal pending old-user irreplaceable state
→ clear old-user in-memory views
→ switch auth scope
→ load new-user cache/drafts
```

A pending Match command from User A can never execute using User B credentials.

# 3. Quick authority handoff matrix

| Handoff state | Authority | Permitted mutation | Network action | Recovery |
|---|---|---|---|---|
| `LOCAL_OWNED` | local device | full Quick local commands | optional explicit Publish | local backup/recovery |
| `HANDOFF_IN_FLIGHT` | transitional; local source frozen enough for command | no divergent edits that would invalidate sent graph | `PublishQuickSession(command_id)` | await authoritative result |
| `HANDOFF_UNKNOWN` | ambiguous; **must not assume local authority** | freeze authority-sensitive edits | retry same `command_id` / query receipt | resolve whether server owns Session |
| `SERVER_OWNED` | server | shared semantic commands only | normal online architecture | loss of network does not revert to local-owned |
| definite Publish rejection before commit | local device | may resume local authority after rejection is known | fix/republish later | server has no target source fact for rejected command |

Target IDs are final UUIDs before handoff. There is no `local_id → cloud_id` remapping protocol.

# 4. Community Match offline protocol matrix

This row family remains rollout-dependent on `OPEN-MATCH-001` and `HYP-PX-001`. The **protocol shape** is accepted even if first release chooses online-only Community scoring.

| Field/context | Purpose | Authority |
|---|---|---|
| `command_id` | logical idempotency | client generates stable ID; server dedupes |
| `match_id` | target aggregate | canonical Match identity |
| prior `control_epoch` | fencing against takeover | server issued |
| `expected_last_sequence` / base | expected source position | server projection snapshot |
| command type/payload | allowlisted sporting intent | client proposes; server validates |
| local ordered position | preserve local replay order | device local only; cannot override server sequence |
| local persisted timestamp | UX/diagnostics | not authoritative ordering |
| User/device scope | prevent cross-account replay | auth + local scope |

Reconnect outcomes:

```text
server epoch same
+ server sequence matches expected chain
→ replay pending commands in order with same command_ids

server epoch changed
OR server source advanced incompatibly
→ RECONCILIATION_REQUIRED

NEVER
→ keep mine / keep theirs / latest timestamp wins
```

# 5. Connectivity / dependency state matrix

| Dimension | States | Meaning |
|---|---|---|
| TransportConnectivity | `ONLINE / OFFLINE / UNKNOWN` | browser/network hint; `navigator.onLine` is only one input |
| BackendReachability | `REACHABLE / DEGRADED / UNREACHABLE / UNKNOWN` | real API/database reachability |
| AuthReadiness | `READY / REFRESHING / EXPIRED / UNKNOWN` | whether authoritative command can authenticate now |
| RealtimeHealth | `CONNECTED / RECONNECTING / UNAVAILABLE / UNKNOWN` | transport acceleration only |
| StorageHealth | `AVAILABLE / DEGRADED / UNAVAILABLE` | Media/provider capability; not Match/Registration truth |
| LocalDurability | `AVAILABLE / QUOTA_PRESSURE / FAILED` | whether critical offline local facts can be safely persisted |

A UI may therefore show:

```text
backend reachable
Realtime unavailable
Registration usable through command/query
spectator auto-updates degraded
```

without declaring the entire app “offline”.

# 7. Subscribe / snapshot / gap protocol

Canonical client convergence:

```text
1. authorize + subscribe
2. buffer incoming semantic events
3. fetch authoritative snapshot/read model
4. record snapshot revision or last_sequence
5. discard buffered events <= checkpoint
6. apply only contiguous compatible events > checkpoint
7. detect gap/schema mismatch
8. refetch/range reconcile instead of guessing
9. enter LIVE state
```

Why subscribe first?

```text
fetch snapshot
→ mutation commits
→ subscribe
```

would create an unobservable gap.

Realtime delivery may be:

```text
delayed
duplicated
out of order
lost
```

and correctness must still converge.

# 8. Realtime publisher / channel security matrix

| Concern | Policy |
|---|---|
| authoritative domain publisher | trusted DB/server path |
| ordinary client publish | receive-only by default for authoritative domain events |
| channel visibility | private by default |
| public Match channel | only separate explicit spectator contract if product/privacy Open closes |
| channel authorization | actual resource/context membership/visibility |
| command authorization | always repeated independently on server |
| socket revocation lag | minimize payload; never rely on socket alone for write security |
| schema version | unknown incompatible version → refetch/upgrade, never heuristic parse |
| ordering | revision/sequence, never event arrival timestamp |

| Data/work | Criticality | Loss consequence | Recovery source |
|---|---|---|---|

| OfficialCompetitionResult revisions | C0 source fact | wrong official outcome/standings | source revisions + backup |
| PlayerEvaluation revisions | C0 source fact | rating history/profile wrong | source evaluation history |

| Projection | Source truth | Freshness checkpoint | Rebuild action | May rebuild automatically? |

| MatchProjection | effective MatchEvents + MatchRulesSnapshot | last sequence | replay deterministic Match reducer | yes if sources intact |

| GlobalSkillProfile | CommunitySkillProfiles + global policy version | profile revisions | recompute hierarchy | yes |
| PlayerMatchStatContribution | Match facts/participation + stat definition version | Match sequence/result revision | rebuild affected Match contribution | yes |
| CareerProjection | effective contributions + eligibility version | contribution checkpoint | recompute affected Player/range | yes |

Automatic repair stops where source truth is ambiguous. Example:

```text
two active Community Owners found because of manual corruption
```

must not be “fixed” by deleting one arbitrarily. That is a governance/data-repair incident.

# 11. Retry class matrix

| Failure class | Example | Automatic retry | Identity reused | Backoff | Notes |
|---|---|---:|---|---|---|
| safe read transient | query timeout | yes bounded | new request_id | exponential+jitter | no mutation uncertainty |
| known-not-committed mutation transient | DB deadlock transaction rolled back | yes bounded | same command_id, new request_id | bounded jitter | server must know rollback/no commit |
| unknown mutation outcome | HTTP timeout after possible commit | yes recovery | **same command_id** | bounded | receipt/idempotency resolves one logical effect |
| validation/domain rejection | Registration closed | no blind retry | n/a | no | refetch/fix input/state |
| authorization denial | removed Membership | no | n/a | no | reauth only if session genuinely stale; server DB state wins |
| stale revision | TeamDraw/Registration conflict | not blind | same/new logical command only after user/system decides | no generic backoff | refetch current state |
| stale Match sequence | expected 80, server 81 | no generic retry | command not silently rebased | no | reconcile/refetch; preserve sporting intent explicitly |
| old control epoch | takeover happened | no auto-apply | pending command preserved for reconcile decision | no | fencing safety |
| provider 429/5xx | Push/Email | yes worker policy | same delivery/intent | bounded, Retry-After when available | domain source already committed |
| provider permanent invalid endpoint | invalid push token | terminal/disable endpoint | same logical delivery | no infinite retry | Inbox remains |
| poison worker item | malformed permanent payload | finite attempts then quarantine | same job/effect identity | bounded | unrelated queue continues |

# 13. Restore / disaster matrix

| Restored/recovered component | Post-restore mandatory verification |
|---|---|
| Postgres source facts | migrations/schema compatibility, FK/unique/invariant checks, ownership/FIFO/Match sequence integrity |
| MatchProjection | replay sample/full affected Matches and compare |
| Statistics/Skill/Standings projections | rebuild/checkpoint comparison |
| domain outbox | identify already-applied/external-effect risk; do not blind replay stale items |
| scheduled Notifications | revalidate source relevance/expiry/preferences before delivery |
| Storage/Media | DB↔blob integrity; missing derived variants regenerate; missing master escalates |
| privacy deletion state | reapply deletion/anonymization obligations that occurred after backup timestamp |
| command receipts | acknowledge finite retention; never claim unlimited historical idempotency |
| auth links/memberships | security/resource access validation before production reopen |

```text
BACKUP EXISTS
≠
RECOVERY PROVEN
```

A successful restore drill records actual evidence; numerical RPO/RTO remains open until business requirement + infrastructure prove it.

# 14. Reliability observability anchors

At minimum, reliability can answer:

| Area | Signals |
|---|---|
| commands | attempts, logical command outcome, unknown outcomes, duplicates/receipts, latency |
| Registration | lock wait, Join/Leave latency, capacity/FIFO integrity anomalies |
| Match | stale sequence, stale epoch, takeover, reconciliation, event/projection integrity |
| local durability | IndexedDB write failures, outbox depth/oldest pending, sealed-account mismatch |
| Realtime | gap count, reconnects, snapshot recovery, propagation latency |
| workers | pending count, oldest age, attempts, lease reclaim, quarantine |
| projections | source checkpoint lag, rebuild failures, stale count |
| backup/restore | last successful backup **and** last successful tested restore evidence |

Telemetry failure normally cannot fail a committed domain command; semantic audit required by a particular privileged transition may have stricter atomicity according to its owner policy.

# 16. C5.04 exit criteria

C5.04 is complete when implementation can answer:

1. whether each operation is online-authoritative, offline-owned, cached, draft, local computation or conditionally offline;
2. what data is locally irreplaceable versus recreateable;
3. how account switch isolates local state;
4. how Quick authority handoff avoids dual authority;
5. how Match offline continuity differs from generic sync;
6. which Realtime mode/checkpoint/payload each context uses;
7. how snapshot/gap/reconnect convergence works;
8. what happens when each dependency fails independently;
9. what is source fact versus rebuildable projection in recovery;
10. how retries distinguish known rollback, unknown outcome, stale state and provider failure;
11. how restore avoids duplicate side effects and privacy resurrection;
12. which reliability policies remain evidence-triggered rather than silently configured.
