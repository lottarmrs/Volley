# 0. Governing rule

Performance and testing are constrained by domain correctness.

```text
FAST + WRONG
=
FAILURE
```

and:

```text
HIGH COVERAGE
≠
INVARIANT PROVEN
```

The target order is:

```text
correct boundary
→ bounded work
→ observable behavior
→ executable invariant evidence
→ measured optimization
```

No performance optimization may weaken Security, LGPD, FIFO, Match ordering, idempotency or historical truth.

# 2. Query / index / RLS matrix

| Concern | Target policy | Anti-pattern | Measurement / test |
|---|---|---|---|
| growing list | explicit page/cursor | fetch all + client filter | rows returned, payload bytes, latency |
| deep history | keyset/cursor where ordering supports it | large OFFSET on hot/deep feeds | plan/latency at depth |
| read fields | select purpose-required columns | `select('*')` on wide historical rows | contract + payload size |
| relational traversal | deliberate join/read model | N+1 query per participant/row | query count/trace |
| indexes | driven by query/invariant | index every column | `EXPLAIN ANALYZE`, write amplification, usage |
| partial active uniqueness | partial unique index where state semantics justify | application-only duplicate prevention | DB constraint tests |
| Registration FIFO | index Window + active waitlist + queue sequence | sort by `updated_at` / client-side scan | plan + concurrent promotion load |
| Match event lookup | `(match_id, sequence)` uniqueness/index | `point_ids[]` / full JSON scan | append/read benchmark |
| RLS | supporting indexes/helpers/read models | disable RLS for speed | plan under realistic auth context + BOLA load |
| projections | read optimized but rebuildable | projection treated as editable fact | rebuild/integrity tests |
| partitioning | only measured trigger | partition MatchEvents preemptively | index/vacuum/restore/table-size evidence |

Investigation ladder before specialized infrastructure:

```text
1 remove unnecessary work
2 bound data set
3 fix query shape
4 fix/add index
5 introduce read model/projection
6 reduce payload/round trips
7 batch safely
8 optimize algorithm/data structure
9 cache with explicit invalidation
10 scale component
11 add specialized infrastructure with measured trigger
```

| Change type | Minimum PR/merge evidence | Additional release/rehearsal |

# 15. Flakiness / reproducibility matrix

| Failure pattern | Policy |
|---|---|
| property test fails randomly | record/replay seed; counterexample becomes regression test |
| concurrent DB test intermittent | investigate race/environment; never hide behind many retries as permanent solution |
| E2E flaky browser timing | own/quarantine temporarily with explicit remediation; critical path cannot be permanently ignored |
| solver differs only on slower CPU | architectural failure if canonical fixed input/seed/version/budget changed result |
| test passes after retry | retry is diagnostic evidence, not proof of health |
| environment leaked production config | hard guard must block test/load tool startup |
| cleanup scope ambiguous | fail closed; never broad-delete shared environment resources |

# 16. Architecture fitness-function matrix

Fitness functions are executable architecture guards with lifecycle.

| Fitness rule | Owner | Desired target | Removal/evolution trigger |
|---|---|---|---|
| UI/Application cannot import infra Supabase directly outside adapters | Application | boundary enforced | update only through ADR/boundary change |
| Domain/Application cannot depend on React | Application | pure application/domain | permanent unless architecture materially changes |
| target solver contract contains no Overall input | Team Formation | permanent guard | only superseding ADR could change, currently high-stability |
| new target modules do not import legacy generic sync | Migration/Governance | monotonic legacy isolation | delete test when legacy path removed and stronger boundary replaces it |
| no service-role secret/VITE misuse in client | Security | permanent | never removed, implementation may evolve |
| privileged RPC search_path/grants hardened | Security/Data | static DB migration check | permanent class of check |
| schema builds from migrations | Data/Ops/QA | fresh DB migration test | permanent |
| architecture docs/catalog references resolve | Governance | no stale links/IDs | permanent registry consistency check |

Existing fitness tests that protect `LocalSyncPayload`, `selectedPlayerIds` or other legacy contracts must be replaced/retired as those targets migrate; “test exists” is not proof the tested architecture is still desired.

# 18. C5.05 exit criteria

C5.05 is complete when implementation planning can answer:

1. what bounds each hot operation;
2. what query/index/read-model strategy avoids total-history work;
3. what performance optimization is prohibited because it weakens correctness/security;
4. what signals distinguish domain failure, technical failure, contention and projection lag;
5. how request/command/job/release identities correlate;
6. which data cannot become metric labels/log payload;
7. what test layer actually owns each critical invariant;
8. which Q0/I0/I1 rules require real DB/RLS/concurrency/rebuild/restore evidence;
9. what CI/release gate follows from change risk;
10. which numeric budgets and scaling technologies remain evidence-triggered rather than architecture guesses.
